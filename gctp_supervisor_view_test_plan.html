Automation Feasibility, Verified Endpoints & Roadmap

Summary of verified endpoints, automation readiness, and test execution priority roadmap.

1. Verified API Endpoints vs Assumed Endpoints

  • Verified CMS Backend API: `https://gctp.in/api/fusion-cms-web-backend/{module}?approvalStatus=all` (Confirmed via existing codebase utilities: `apis/CmsTamilHomeApi.ts`, `apis/CmsTamilABTApi.ts`, and `tests/cms-vs-website-comparison/CmsTamilContactUsApi.spec.ts`).
  • Verified Public Facing API: `https://gctp.in/api/fusion-public-facing-web-backend/{module}` (Confirmed for Home, About Us, Contact Us, News, Media).
  • Assumed UI Selectors: Exact CSS classes for React Supervisor approval/rejection buttons assume standard component library naming conventions and will be inspected during live runtime execution.

2. Test Case Breakdown & Execution Priority

  • Total Test Cases: 36 Unique Test Cases covering all 18 functional areas.
  • Priority 0 (P0 - 10 Test Cases): Supervisor Authentication, Access Control, Content Approval/Rejection Workflows, API Endpoint Contracts, and Public Isolation. *(Smoke & CI Gate — Must Pass 100%)*
  • Priority 1 (P1 - 14 Test Cases): Table Schema Validation, Master Content List, Complaint List, CMS Audit Logs, Tamil/English Bilingual Parity, Deep Links, Back/Forward Navigation. *(Nightly Regression Suite)*
  • Priority 2 (P2 - 12 Test Cases): Global Search, Row Preview, Feedback List, Social Media Links, Notification/Profile Menus, Table Horizontal Scrolling, Timestamp Ordering, Empty States. *(Pre-Release Verification)*

3. Unresolved Application Requirements

  • Confirmation of exact supervisor permission flags required in CMS user roles database for cross-department approvals.
  • SLA timing for automatic cache invalidation on public website (`https://gctp.in`) after a CMS approval action.
  • Presence of rate-limiting or anti-CSRF token headers on CMS mutation POST/PUT endpoints.
Important QA Rule: Never promote pending or rejected content to public visibility under any circumstance. All approval workflows must be verified with automated assertions across both CMS backend APIs and public frontend pages.
